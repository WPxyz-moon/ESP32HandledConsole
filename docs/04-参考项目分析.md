> 参考对象：OSHWHub「ESP32S3多功能手柄」与其 GitHub 仓库 `zistar001/ESP-Handheld`。  
> 用途：作为硬件选型、软件架构、分区方案与踩坑经验的参考，不直接照搬其完整功能集。

## 3. 参考项目的软件架构拆解

### 3.1 目录结构（节选）

```text
main/
  main.c                入口、初始化序列、按键分发
  bsp/                  板级支持：ST7789、SD 卡、按键、板级定义
  app/                  应用框架：app_manager、launcher、menu、rom_browser
  modules/              功能模块：audio、imu、sensor、weather、pc_remote、
                        wifi_manager、settings、theme、spectrum、iching、
                        retro_go、power、time_sync
  ui/                   LVGL 屏幕、组件、显示驱动
components/
  lvgl/                 LVGL v8.4（子模块）
  retro-core/           nofrendo NES 核心
  retro-go/             Retro-Go 运行时
  esp-wifi-connect/     Wi-Fi 配网（子模块）
retro-go-firmware/      ota_0 独立游戏固件
xiaozhi-zistar-main/    ota_1 小智 AI 固件
partitions.csv          三分区表
docs/                   硬件、编译、烧录、用户手册
scripts/                构建/环境脚本
```

### 3.2 三固件与分区

参考项目的 16MB Flash 划分：

| 分区 | 偏移 | 大小 | 内容 |
|---|---|---|---|
| `factory` | `0x10000` | 4MB | 主系统（LVGL 菜单、设置、BLE、Wi-Fi 音频等） |
| `ota_0` | `0x410000` | 4MB | Retro-Go 游戏系统 |
| `ota_1` | `0x810000` | 4MB | 小智 AI |
| `assets` | `0xC10000` | 约 4MB | SPIFFS 资源 |

> 仓库里的 `partitions.csv` 注释与 OSHWHub 描述在 `ota_0/ota_1` 用途上略有差异（一处写 XiaoZhi A/B OTA，一处写游戏/AI）。落地时以实际烧录的固件为准，并在自己的仓库里把注释写清楚。

### 3.3 主系统初始化顺序

参考项目 `main.c` 的顺序大致是：

```text
NVS → 设置/主题 → SD 卡 → BSP 板级（LCD）→ LVGL → 音频 → 传感器
→ 电池 → BLE HID → 空中飞鼠 → Wi-Fi → 天气/时间 → 按键 → 电源管理 → App Manager
```

对本项目的启示：

- **Wi-Fi/天气必须异步**，不能阻塞 UI。
- **按键在初始化完成前不处理**，否则初始化期间误触会触发页面切换甚至重启。
- **Launcher 的定时刷新任务**（时间/电量/Wi-Fi）用 1s 周期 + LVGL 锁，避免竞态。
- **先设置状态，再创建界面**，防止后台任务读到旧状态访问已删除的 screen 对象。

### 3.4 应用状态机

参考项目是 `Launcher ↔ Menu → Running` 三态：

```text
Launcher --START--> Menu --A--> Running
   ↑                  |            |
   └----B/START-------┘            |
   └-----------B/START-------------┘
```

本项目沿用该状态机，但把“游戏”和“AI”改成**切固件**，而不是同固件内的页面：

- 主系统菜单点“游戏” → 保存设置 → `esp_ota_set_boot_partition(ota_0)` → 重启。
- 主系统菜单点“AI” → 保存设置 → `esp_ota_set_boot_partition(ota_1)` → 重启。
- 子固件内 `START+B` → 切回 `factory`。

### 3.5 音频与显示的关键配置

| 项 | 参考做法 | 本项目建议 |
|---|---|---|
| 显示总线 | ST7789 走 SPI2，SD 走 SPI3 | 沿用，避免总线争用 |
| 颜色格式 | RGB565，ST7789 需要字节交换 | 开启 `LV_COLOR_16_SWAP`，RAW 数据手动交换 |
| ST7789 COLMOD | SPI 模式用 `0x05`，不是 `0x55` | 沿用，否则颜色异常 |
| 背光 | GPIO43 PWM | 沿用，低电时降亮度 |
| 麦克风 | MSM261，I2S0 RX | 沿用，16kHz/16bit |
| 功放 | MAX98357，I2S1 TX | 沿用，注意上电 12ms 稳定时间 |
| 麦克风增益 | 软件乘法器 0–37dB | 沿用，提供设置项 |
| PSRAM | 8MB Octal | 帧缓冲/音频缓冲放 PSRAM，DMA 用内部 RAM |

### 3.6 游戏系统

参考项目有两条路径：

1. **主系统内嵌 NES**：`components/retro-core`（nofrendo）+ `modules/retro_go` 桥接，启动快，但会占用主固件内存。
2. **独立 Retro-Go 固件（ota_0）**：完整游戏系统，支持多机种、存档、列表，内存隔离好。

本项目采用第 2 条作为正式方案；第 1 条可作为“主系统快速试玩”的可选增强，但首版不做，避免主固件过大。

### 3.7 AI 系统

参考项目的 `xiaozhi-zistar-main/` 是小智 AI 的定制版，已包含：

- 自定义板级定义（ST7789、MAX98357、MSM261、按键）
- 语音上行/下行链路
- Wi-Fi/BLE 配网
- `START+B` 返回主系统
- OTA/设置/状态机

本项目可复用其**板级配置与语音链路**，但需要新增：

- 文本输入界面（LVGL 键盘）与 HTTPS 流式对话
- 图形化 AI 宠物（表情、动画、按键/IMU/语音三模态）
- 更完整的电源管理（参考项目 AI 固件不读电池 ADC，电量固定 100%）

## 5. 必须改造的部分

### 5.1 增加 CTRL 键与键盘映射

参考项目只有 7 键，没有 CTRL。本项目要求：

- 硬件增加第 8 键（建议 GPIO47），或长按 START 复用；
- HID 键盘模式下实现 `Ctrl+A/X/V/C` 的方向键映射；
- 设置页提供“方向键映射 / 标准 Ctrl 映射”切换。

### 5.2 增加图形化 AI 宠物

参考项目的 AI 是小智语音助手（偏对话），没有完整的宠物养成/表情互动。本项目需要：

- LVGL 表情/动画资源（至少 6 种表情：开心、困、饿、晕、睡、惊讶）；
- 状态机（Idle/Listening/Thinking/Speaking/Reacting/Sleeping/Error）；
- IMU 摇晃/倾斜/翻转识别；
- 本地反应优先，断网可玩；
- 与语音/文本对话联动（说话时宠物有口型/表情）。

### 5.3 修复电源与休眠

参考项目明确提到“休眠后会睡死唤不醒，可按 RESET 重启”。本项目不能接受：

- 只用 Light Sleep，不用默认深睡；
- 用 GPIO 唤醒，唤醒后重新初始化 I2S/背光；
- 100 次睡眠/唤醒测试；
- 低电保护独立于休眠，先保存再睡。

### 5.4 删减功能，控制固件体积

参考项目 4MB 主固件里塞了天气、占卜、频谱、NES 等。本项目删掉这些后，主固件会更小，但仍需注意：

- LVGL 中文字体很大，按需裁剪字符集；
- 宠物动画资源放 `assets` 分区，不塞进应用分区；
- 每个应用分区控制在 4MB 内，编译后检查 `idf.py size`。

### 5.5 屏幕与结构适配

- 参考项目用 1.69 寸 240×280 裸屏，屏幕很脆弱；装配时用 2mm 泡沫双面胶，避免压碎。
- 外壳 STL 可参考，但按键位置、CTRL 键、电池仓需要按自己的板子修改。
- 天线用 IPEX 1 代外接天线，远离电池和金属。

## 6. 参考项目的已知坑（务必提前规避）

| 坑 | 现象 | 规避方法 |
|---|---|---|
| RGB565 字节序 | 颜色错乱/偏色 | 开 `LV_COLOR_16_SWAP`，RAW 像素手动交换 |
| ST7789 COLMOD | SPI 模式下颜色异常 | 用 `0x05`，不要用 RGB 接口的 `0x55` |
| PSRAM DMA | 刷屏/音频崩溃 | DMA buffer 用内部 RAM，帧缓冲放 PSRAM |
| LVGL 堆不足 | 页面切换后崩溃 | 及时 `lv_obj_del`，堆 64–96KB，监控水位 |
| `ota_data_initial.bin` 缺失 | 启动到错误分区 | 全量烧录必须写 `0xd000` |
| FreeRTOS 1000Hz tick | 延时/超时比预期快 10 倍 | 明确 `pdMS_TO_TICKS`，不要按 100Hz 估算 |
| 休眠睡死 | 唤醒无反应 | 只用 Light Sleep + GPIO 唤醒，充分测试 |
| 初始化期间按键 | 误触导致重启 | 系统 ready 标志之前忽略按键 |
| 屏幕压碎 | 裸屏裂 | 泡沫双面胶固定，装配避免受力 |
| 天线/电池干扰 | Wi-Fi 距离短 | 天线净空，远离电池/金属 |
| MSYS2 环境 | ESP-IDF 拒绝构建 | 用 PowerShell/cmd，不要用 MSYS2 |
| 商业 ROM | 版权风险 | 只用 homebrew/自有 ROM 测试 |

## 9. 结论：参考项目对我们的价值

**能给的**：

- 一套验证过的 ESP32-S3 掌机硬件组合与引脚基线；
- 三固件分区 + 菜单切换的完整思路；
- LVGL 主系统框架、BLE HID、Wi-Fi 音频、Retro-Go、XiaoZhi 的可复用代码；
- 大量真实踩坑经验（显示、内存、休眠、焊接、结构）。

**不能直接给的**：

- CTRL 键与指定键盘映射；
- 图形化 AI 宠物与多模态互动；
- 稳定的电源/休眠（参考项目有已知问题）；
- 我们自己的外壳、PCB、UI 与文档。

**正确姿势**：把它当“已验证的技术底座”，先跑通，再做减法与增量，最后形成我们自己的三固件掌机。
