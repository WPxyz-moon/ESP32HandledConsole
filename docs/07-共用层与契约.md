# 07 · 共用层与契约

> 版本：v0.1（2026-11-24）  
> 关联：[01 系统框图](01-系统框图.md) · [02 子系统流程图](02-子系统流程图.md) · [06 驱动层设计](06-驱动层设计.md)  
> 适用范围：`factory` / `game(ota_0)` / `ai(ota_1)` 三套固件共用的源码层。

本文把“三套固件必须表现一致”的语义固定下来。驱动层边界见 06；本文只写驱动之上的
角色、切固件、设置、存储、事件与共用组件状态。

## 1. 共用层边界

三套固件是三个独立二进制，**源码共享、运行时不同时存在**。共用层包括：

```text
HandledConsole/components/
├── bsp_board/        已有：板名、引脚宏
├── svc_fw_role/      角色识别
├── svc_event/        事件总线
├── svc_ota/          分区切换
├── svc_system/       切固件前的 prepare hook
├── svc_settings/     NVS 设置
├── svc_storage/      待 BSP：NVS/SD/assets 封装
├── svc_power/        待 BSP：背光/休眠策略
├── app_core/         应用生命周期
├── ui_core/          待 BSP：LVGL 页面框架
└── bsp_display/ bsp_input/ bsp_audio/ bsp_imu/ bsp_storage/ bsp_power/
                      待实现：见 06
```

应用代码只依赖头文件，不直接操作 GPIO/SPI/I2S/Flash。

## 2. D1 固件角色

### 2.1 规则

- **编译期**决定固件角色，用于裁剪功能；
- **运行期**从实际分区读取角色，用于校验与日志；
- 两者不一致时记录 ERROR，**不自动切换角色**，继续按编译期角色运行。

### 2.2 Kconfig

每个工程的 `sdkconfig.defaults`：

```ini
# factory
CONFIG_FW_ROLE_FACTORY=y

# game
CONFIG_FW_ROLE_GAME=y

# ai
CONFIG_FW_ROLE_AI=y
```

### 2.3 API

```c
typedef enum {
    FW_ROLE_UNKNOWN = -1,
    FW_ROLE_FACTORY = 0,
    FW_ROLE_GAME = 1,
    FW_ROLE_AI = 2,
} fw_role_t;

fw_role_t fw_role_compiled(void);
fw_role_t fw_role_running(void);
const char *fw_role_name(fw_role_t role);
bool fw_role_check(void);
```

映射：

| 分区标签 | 角色 |
|---|---|
| `factory` | `FW_ROLE_FACTORY` |
| `ota_0` | `FW_ROLE_GAME` |
| `ota_1` | `FW_ROLE_AI` |
| 其他 | `FW_ROLE_UNKNOWN` |

## 3. D2 切固件契约

### 3.1 职责

| 层 | 职责 |
|---|---|
| 业务 app | 保存自己的数据（游戏存档、AI 摘要、宠物状态） |
| `svc_system` | 调用注册的 prepare hook，停音频/网络/无线，flush |
| `svc_ota` | 查找目标分区、校验镜像、设置启动分区、重启 |

`ota_manager` **不保存业务数据**，也不猜测游戏/AI 的存档格式。

### 3.2 调用顺序

```text
用户选择目标
  → app 保存自己的状态
  → system_prepare_switch()
       - 停音频/录音
       - 停 Wi-Fi/BLE
       - 等 DMA/Flash 空闲
  → ota_manager_switch(target)
       - esp_partition_find_first()
       - esp_ota_set_boot_partition()
       - 成功：esp_restart()
       - 失败：返回错误，留在当前固件
```

### 3.3 API

```c
esp_err_t ota_manager_switch(fw_role_t target);
esp_err_t ota_manager_boot_factory(void);
esp_err_t ota_manager_mark_valid(void);
const char *ota_manager_running_label(void);
```

### 3.4 失败处理

| 情况 | 行为 |
|---|---|
| 业务保存失败 | 不切，提示用户 |
| prepare hook 失败 | 记录 WARN；是否继续由调用方决定 |
| 目标分区不存在 | `ESP_ERR_NOT_FOUND`，留在当前固件 |
| 目标镜像无效 | `ESP_ERR_OTA_VALIDATE_FAILED`，留在当前固件 |
| 设置 schema 不兼容 | 启动时迁移；失败使用默认值 |

### 3.5 回滚

- 默认关闭 bootloader rollback，本地切分区不需要 `mark_valid`。
- 若开启 rollback，子固件初始化成功后调用 `ota_manager_mark_valid()`。
- `factory` 始终是无效 `otadata` 的最终兜底。

## 4. D3 NVS 设置

### 4.1 命名空间与 key

单 namespace：`hcfg`。key 使用 `<module>.<item>`，不超过 15 字符。

| key | 类型 | 写者 | 默认 |
|---|---|---|---|
| `sys.schema_ver` | u32 | 系统 | `1` |
| `ui.brightness` | u8 | factory | 70 |
| `ui.theme` | u8 | factory | 0 |
| `audio.volume` | u8 | factory | 60 |
| `net.ssid` | str | factory | `""` |
| `net.pass` | str | factory | `""` |
| `ai.api_key` | str | ai | `""` |
| `ai.model` | str | ai | `"default"` |
| `game.keymap` | blob | game | 默认映射 |
| `pet.state` | blob | ai | 默认状态 |

### 4.2 所有权

| 固件 | 可写 | 可读 |
|---|---|---|
| factory | `ui.*`、`audio.*`、`net.*`、`sys.*` | 全部 |
| game | `game.*` | `ui.*`、`audio.*` |
| ai | `ai.*`、`pet.*` | `ui.*`、`audio.*`、`net.*` |

### 4.3 Wi-Fi 与 BLE

- Wi-Fi 凭据存 `hcfg`，`net_service` 使用 `WIFI_STORAGE_RAM`，启动时
  `esp_wifi_set_config()` 下发，避免第二套 `nvs.net80211` 数据源。
- BLE 绑定由协议栈管理；恢复出厂时调用协议栈 API 清除绑定。

### 4.4 schema 与恢复出厂

- `settings_init()` 打开 `hcfg`，检查 `sys.schema_ver`；
- 旧版本执行迁移，新版本（降级）记录 WARN，未知 key 用默认值；
- `settings_erase_all()` 清 `hcfg`；
- 恢复出厂同时清 Wi-Fi/BLE 绑定；**SD 用户文件保留**，另设“清除 SD 数据”。

### 4.5 NVS 预算

NVS 只有 16KB：

- 不把聊天记录写 NVS；聊天记录写 SD，NVS 只存摘要/宠物状态；
- API Key ≤256B，Wi-Fi 两个字符串，keymap blob ≤64B；
- 新增 key 前先算空间。

## 5. D4 SD 与 assets

### 5.1 固定目录

```text
/sdcard/
  roms/nes/          ROM，用户/下载器写
  saves/nes/         game 写
  ai/                ai 写：chat.jsonl、pet.json
  logs/              可选，默认关闭
  assets/            开发期覆盖，正式版不用

/assets/             只读 SPIFFS
  manifest.json
  fonts/
  images/pet/
  audio/
```

### 5.2 所有权

| 目录 | 写者 | 读者 |
|---|---|---|
| `roms/nes` | 用户/下载器 | game、factory 文件页 |
| `saves/nes` | game | game |
| `ai` | ai | ai |
| `logs` | 诊断（可选） | 诊断 |
| `/assets` | 构建脚本 | 三固件只读 |

### 5.3 原子写入

```text
write  game.sav.tmp
fsync
rename game.sav.tmp -> game.sav
```

保留上一份 `.sav.bak`；读取失败时回退 `.bak`。

### 5.4 文件格式

| 文件 | 格式 |
|---|---|
| NES ROM | 原生 `.nes` |
| SRAM 存档 | 原生 `.sav` |
| 即时存档 | 自定义头 + `version` + 状态 |
| AI 聊天 | JSONL，每行带 `v` |
| 宠物状态 | JSON/二进制，头带 `version` |

### 5.5 assets manifest

```json
{
  "schema": 1,
  "version": "2026-11-24",
  "items": [
    {"id": "pet.idle", "type": "image", "path": "images/pet/idle.rgb565"},
    {"id": "font.cn16", "type": "font", "path": "fonts/cn16.bin"}
  ]
}
```

- 只通过 ID 取资源；
- 缺资源返回 `ESP_ERR_NOT_FOUND`，UI 用内置占位；
- manifest 版本不匹配拒绝加载并 WARN；
- assets 只读。

### 5.6 SD 无卡检测

- 启动重试 3 次，失败不阻塞启动；
- game 提示“请插入 SD 卡”；
- ai 无 SD 可运行，聊天/宠物状态降级到 NVS 或内存；
- 不承诺热插拔；设置页提供“重新扫描”。

## 6. D5 事件总线

### 6.1 事件结构

```c
typedef enum {
    EVT_SYS_BOOT = 0,
    EVT_SYS_POWER,
    EVT_KEY,
    EVT_IMU,
    EVT_NET,
    EVT_AUDIO,
    EVT_APP,
    EVT_TYPE_MAX,
} event_type_t;

typedef struct {
    event_type_t type;
    uint32_t timestamp_ms;

    union {
        struct { uint8_t id, evt; uint16_t state; uint32_t held_ms; } key;
        struct { uint8_t gesture; } imu;
        struct { uint8_t state; int code; } net;
        struct { uint8_t state; } audio;
        struct { uint8_t reason; } sys;
        struct { int code; } app;
    } u;
} app_event_t;
```

约束：

- 按值传递，不放指针；
- 字符串用 ID 或固定长度数组；
- IMU 原始样本不进总线，只发手势；
- PCM 不进总线，走音频环形缓冲；
- 改结构必须同时重编三个固件。

### 6.2 API

```c
esp_err_t event_bus_init(void);
esp_err_t event_bus_subscribe(event_type_t type,
                              event_handler_t handler, void *ctx);
esp_err_t event_bus_post(const app_event_t *ev, TickType_t ticks_to_wait);
esp_err_t event_bus_post_from_isr(const app_event_t *ev);
void event_bus_get_stats(event_bus_stats_t *out);
```

### 6.3 队列与分发

- 全局固定队列 32 条；
- `event_task` 优先级 5，栈 4KB；
- 订阅者按事件类型注册，最多 16 个；
- 回调必须短，禁止阻塞、长文件/网络操作；
- 队列满：丢新事件，`dropped++`；生产者在任务里使用 0 等待；
- 电源/OTA 等关键事件不走总线，直接调用服务。

### 6.4 ISR 与游戏

- 只有按键 GPIO ISR 用 `event_bus_post_from_isr()`；
- ISR 不打印、不分配、不拿互斥锁；
- `game` 帧循环直接读 `bsp_input_state()`，不强制走事件总线；
- `START+B`/长按 START 由 `key_service` 或游戏输入层判断。

接口落地后由 `app_main` 调用 `settings_init()`。

## 8. 变更规则

1. `event_bus.h`、`fw_role.h`、`ota_manager.h`、`settings.h` 是共享 ABI；
   改字段/签名必须同时改三个固件并重新全量编译。
2. 新增 NVS key 必须更新本文第 4 节，并检查 15 字符限制与 16KB 预算。
3. 新增 SD 目录必须更新本文第 5 节，并说明写者/读者。
4. 新增事件类型必须更新本文第 6 节，并说明是否允许丢弃。
5. 新增 prepare hook 必须在 `svc_system` 注册，并保证短、不阻塞。
6. 每周合并前，三个工程都必须 `idf.py build` 通过。
