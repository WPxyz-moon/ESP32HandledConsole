# 06 · 驱动层设计（BSP）

> 版本：v0.1（2026-11-24）  
> 关联：[01 系统框图](01-系统框图.md) · [02 子系统流程图](02-子系统流程图.md) · [05 PCB 核对与改板建议](05-PCB核对与改板建议.md)  
> 适用范围：`factory` / `game(ota_0)` / `ai(ota_1)` 三套固件共用同一份驱动源码。

本文只定义驱动层的边界、接口与验收口径，不代表驱动已经实现。引脚一律以
[board_config.h](../HandledConsole/components/bsp_board/include/board_config.h)
和 PCB 数据文件为准。

## 1. 定位与边界

驱动层就是 BSP 层：向下使用 ESP-IDF 自带的控制器驱动（`esp_lcd`、`i2s_std`、
`i2c_master`、`sdspi`、`ledc`），向上给框架层和应用层提供稳定、与硬件无关的 C 接口。
**不重复实现 ST7789/I2S/I2C 的寄存器级驱动。**

### 1.1 驱动层负责

- 引脚复用、上电默认状态、总线创建与参数配置。
- 外设初始化、反初始化、错误返回、重试策略。
- 缓冲区与 DMA：尺寸、对齐、内部 RAM/PSRAM 的取舍。
- 关键运行统计：欠载、超时、丢键、flush 耗时等。
- 提供最小必要的事件回调，不包含业务判断。

### 1.2 驱动层不负责

- LVGL 页面、主题、中文输入。
- Wi-Fi、BLE HID、HTTP/WebSocket、语音编解码、AI 业务。
- 应用状态机、菜单、存档格式。
- 电量显示、低电保护、充电状态——**硬件没有采样，本版不做**。
- AHT20、IMU 中断、SD 卡检测脚——**硬件未连接，不做对应驱动**。

### 1.3 三条硬约束

1. **日志只做诊断，不参与功能。** 日志不得占用任何功能引脚，不得在 ISR、
   DMA 回调、音频回调、刷屏热路径里输出；关掉日志（`LOG_LEVEL_NONE`）后，
   驱动行为与帧率必须不变。
2. **驱动不依赖上层。** BSP 组件不能包含 LVGL、应用头文件；游戏固件可以
   只用 LCD 驱动直接刷帧，不引入 LVGL。
3. **每次启动重新初始化。** 三套固件切换会重启，驱动不能假设外设寄存器
   还是上一次的状态；所有 `bsp_*_init()` 必须能在冷启动后独立完成初始化。

## 2. 组件划分

```text
HandledConsole/components/
├── bsp_board/        板级早期初始化、板名、公共初始化顺序
├── bsp_display/      ST7789 + SPI2 + DMA + 背光 LEDC
├── bsp_input/        8 键扫描、消抖、短按/长按
├── bsp_imu/          LSM6DS3TR-C 轮询采样

```

| 组件 | 主要源文件 | IDF 依赖（`REQUIRES`） |
|---|---|---|
| `bsp_board` | `board.c` | `esp_driver_gpio`, `esp_driver_ledc` |
| `bsp_display` | `display_st7789.c`, `backlight.c` | `esp_lcd`, `esp_driver_spi`, `esp_driver_ledc` |
| `bsp_input` | `input.c` | `esp_driver_gpio`, `freertos` |

| `bsp_audio` | `audio.c` | `esp_driver_i2s` |
| `bsp_storage` | `storage.c` | `fatfs`, `esp_driver_sdspi`, `spiffs`, `nvs_flash` |
| `bsp_power` | `power.c` | `esp_driver_gpio`, `esp_hw_support` |

三个工程的 `main/CMakeLists.txt` 只需在 `REQUIRES` 里增加实际用到的 `bsp_*`
组件；未用到的驱动不会链接进固件。

## 3. 初始化顺序

```text
app_main
  │
  ├─ bsp_board_early_init()      ← 第一行：GPIO44 拉低关背光、LED 熄灭
  ├─ bsp_storage_nvs_init()      ← NVS 供设置/Wi-Fi/BLE 使用
  ├─ bsp_display_init()          ← SPI2 + ST7789；先不点亮背光
  ├─ bsp_input_init()            ← 8 键；初始化完成前不派发按键
  ├─ bsp_imu_init(100)           ← I2C + 100Hz 轮询任务
  ├─ bsp_audio_init()            ← I2S0 RX / I2S1 TX
  ├─ bsp_storage_init()          ← SD 挂载（失败非致命）+ assets
  ├─ bsp_power_init()            ← LED / 唤醒源
  ├─ bsp_display_set_backlight() ← 屏幕初始化完成后再亮
  └─ event_bus_init() → app_manager_start()
```

顺序理由：

- 背光电路 Q2 基极有 10 kΩ 上拉到 3V3，**上电默认常亮**，必须尽早拉低，
  否则屏幕未初始化时会出现白屏/闪白。
- 按键中断必须在系统初始化完成后才派发，避免初始化期间误触触发业务逻辑。
- SD 卡挂载失败不能阻塞启动；主系统跳过，游戏系统提示，AI 系统不受影响。
- 音频最后初始化，避免 I2S DMA 在屏幕/存储还没就绪时抢总线。

`bsp_board_init()` 提供上述公共序列的便捷封装；如果某个固件不需要某个外设
（例如主系统不需要 IMU 高频采样），可以直接调用单独的 `bsp_*_init()`。

## 4. 通用接口约定

- 命名：`bsp_<模块>_<动作>()`，头文件放在 `include/bsp_<模块>.h`。
- 返回值：统一 `esp_err_t`；驱动内部不调用 `ESP_ERROR_CHECK`，由调用方决定
  是否致命。`ESP_ERROR_CHECK` 只允许出现在 `app_main` 的必需初始化上。
- 句柄：每个外设一个静态单例，驱动内部持有；上层不直接操作 IDF 句柄。
- 反初始化：`bsp_*_deinit()` 必须可重复调用，未初始化时返回 `ESP_OK`。
- 线程：`init/deinit` 只允许在创建业务任务之前调用；运行期 API 明确标注
  是否线程安全。ISR 里只允许入队，不允许打印、分配内存、拿互斥锁。
- 错误日志：驱动只记录一次关键错误（初始化失败），不周期性刷日志。
- 引脚：任何源文件不得出现裸 GPIO 数字，一律使用 `BSP_*` 宏。

## 5. 日志与可观测性（不影响功能）

### 5.1 控制台只走 USB Serial/JTAG

本板没有 CH340/CP2102，UART0 的 GPIO43/44 又被 LCD_DC/LCD_BL 占用。
**控制台必须使用原生 USB Serial/JTAG（GPIO19/20）**，三份 `sdkconfig.defaults`
统一加入：

```ini
# 控制台：只用 USB Serial/JTAG，绝不占用 LCD 引脚
CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y
# CONFIG_ESP_CONSOLE_UART_DEFAULT is not set
CONFIG_ESP_CONSOLE_SECONDARY_NONE=y

CONFIG_LOG_DEFAULT_LEVEL_INFO=y
```

- `sdkconfig` 的优先级高于 `sdkconfig.defaults`；改完默认值后要删除三个工程
  已有的 `sdkconfig`（或 `idf.py fullclean`）重新生成。
- 烧录/监视统一用 `idf.py -p <USB口> flash monitor`。
- 复位瞬间 ROM bootloader 仍可能在 UART0 输出极少量字符，此时 LCD 尚未
  初始化，属于无害瞬态；不需要为此改硬件或烧 efuse。
- 禁止使用 `printf`/`putchar` 直接写控制台；统一 `ESP_LOGx`。

### 5.2 分级与热路径

| 位置 | 允许的日志 |
|---|---|
| `bsp_*_init/deinit` | 每个模块一条 INFO；失败一条 ERROR |
| 按键/IMU 任务 | 默认不打印；调试时可用 DEBUG，量产关闭 |
| LCD flush / DMA 回调 | **禁止**任何日志 |
| I2S 读写 / DMA 回调 | **禁止**任何日志 |
| ISR | **禁止**任何日志 |
| 网络/UI 业务 | INFO/WARN，按模块 TAG 控制 |

需要观测热路径时，用统计接口而不是日志：

```c
typedef struct {
    uint32_t flush_count;
    uint32_t flush_timeout;
    uint32_t last_flush_us;
} bsp_display_stats_t;

typedef struct {
    uint32_t mic_overrun;
    uint32_t spk_underrun;
    uint32_t bytes_rx;
    uint32_t bytes_tx;
} bsp_audio_stats_t;
```

对应 `bsp_display_get_stats()`、`bsp_audio_get_stats()`、`bsp_input_get_stats()`、
`bsp_imu_get_stats()`。上层调试页面或串口命令按需读取，驱动本身不主动打印。

### 5.3 发布配置

联调阶段保持 `CONFIG_LOG_DEFAULT_LEVEL_INFO`；演示/发布前改为 `WARN`，
并在 `app_main` 里按需调用 `esp_log_level_set("bsp_*", ESP_LOG_WARN)`。
验收时必须分别在 `INFO` 和 `WARN` 下跑一遍，确认功能、帧率、音频无差异。

## 6. 各驱动设计

### 6.1 bsp_board

```c
esp_err_t bsp_board_early_init(void);
esp_err_t bsp_board_init(void);
const char *bsp_board_name(void);
```

- `early_init()`：把 GPIO44 配置为输出并拉低（NPN 低边，高电平点亮，所以低 =
  背光灭）；GPIO18 配置为输出并拉高（LED 低电平点亮，所以高 = 灭）。
- `init()`：按第 3 节顺序调用各驱动，任一必需外设失败则返回错误；SD 失败
  只记录警告。
- 板名仍返回 `BSP_BOARD_NAME`，日志/UI 共用。

### 6.2 bsp_display

**硬件**：ST7789 240×280，SPI2：SCK=21、MOSI=14、CS=42、DC=43、RST=13、
BL=44。控制器显存 240×320，`y_gap = 20`。背光为 NPN 低边 PWM，高电平点亮。

**配置**：

| 项 | 取值 |
|---|---|
| 总线 | `SPI2_HOST`，MOSI/SCK 专用 IO，最大传输 32 KB/次 |
| 时钟 | 先 40 MHz 稳定后，再评估 60–80 MHz |
| 面板 | `esp_lcd_new_panel_st7789`，RGB565，`reset_gpio_num=13` |
| 偏移 | `esp_lcd_panel_set_gap(panel, 0, 20)` |
| 背光 | LEDC 5 kHz，10 bit，GPIO44，占空比 0–100% |
| DMA | 异步 `on_color_trans_done` 回调 + 完成信号量 |

**缓冲策略**：

- 驱动内部维护两块**内部 RAM** bounce buffer（各 16 KB），所有
  `bsp_display_flush()` 先把数据按块拷入 bounce buffer 再启动 DMA，避免
  PSRAM 直接做 SPI DMA 的兼容性问题。
- LVGL 使用两块局部缓冲（建议 240×40，每块 19.2 KB，内部 RAM），由 LVGL
  适配层调用 `bsp_display_flush()`。
- NES 使用一块 PSRAM 全帧缓冲（240×280×2 = 134.4 KB），按 2–4 块调用
  `bsp_display_draw()`；驱动内部同样走 bounce buffer。

**接口**：

```c
esp_err_t bsp_display_init(void);
esp_err_t bsp_display_deinit(void);
esp_err_t bsp_display_flush(int x1, int y1, int x2, int y2, const void *rgb565);
esp_err_t bsp_display_draw(int x, int y, int w, int h, const void *rgb565);
esp_err_t bsp_display_set_backlight(uint8_t percent);   /* 0–100 */
esp_err_t bsp_display_get_stats(bsp_display_stats_t *out);
int bsp_display_width(void);
int bsp_display_height(void);
```

- `flush/draw` 默认阻塞到 DMA 完成；提供 `bsp_display_wait_idle()` 供需要
  双缓冲重叠的上层使用。
- 初始化失败重试 3 次；仍失败则返回错误，由 `app_main` 决定是否点亮背光
  做提示（见 [02 §5](02-子系统流程图.md)）。
- 热路径不打印日志，只累加 `flush_count`、`flush_timeout`。

**注意事项**：

- 不要在 `on_color_trans_done` 回调和 flush 中调用 `ESP_LOGx`。
- 屏幕 Y 偏移 20 必须设置，否则底部 20 行会错位到顶部。
- 背光 PWM 与 LED 的极性相反：背光高有效，LED 低有效。

### 6.3 bsp_input

**硬件**：8 键，低有效，内部上拉；UP=16、DOWN=15、LEFT=17、RIGHT=7、
A=4、B=5、START=6、CTRL=8。

**行为**：

- GPIO 双边沿中断只负责记录时间戳并入队（队列长度 32），不做消抖。
- 驱动任务每 5–20 ms 扫描队列与当前电平，**20 ms 消抖**；产生
  `DOWN/UP/LONG/REPEAT` 事件。
- 长按阈值默认 1000 ms，可配置；组合键（如 `START+B` 1.5 s、`CTRL+方向`）
  由上层 `key_service` 根据按键状态位判断，驱动只提供单键事件与状态位。
- 初始化完成前不派发事件；初始化完成后先做一次全键电平采样，避免把
  "上电时已按住"误判为按下。
- 回调在驱动任务上下文执行，禁止在回调里阻塞超过 10 ms。

**接口**：

```c
typedef enum {
    BSP_KEY_UP = 0, BSP_KEY_DOWN, BSP_KEY_LEFT, BSP_KEY_RIGHT,
    BSP_KEY_A, BSP_KEY_B, BSP_KEY_START, BSP_KEY_CTRL,
    BSP_KEY_COUNT
} bsp_key_id_t;

typedef enum {
    BSP_KEY_EVT_DOWN = 0, BSP_KEY_EVT_UP,
    BSP_KEY_EVT_LONG, BSP_KEY_EVT_REPEAT
} bsp_key_evt_t;

typedef struct {
    bsp_key_id_t id;
    bsp_key_evt_t evt;
    uint32_t held_ms;
} bsp_key_event_t;

typedef void (*bsp_key_cb_t)(const bsp_key_event_t *ev, void *ctx);

esp_err_t bsp_input_init(bsp_key_cb_t cb, void *ctx);
esp_err_t bsp_input_deinit(void);
uint32_t bsp_input_state(void);              /* 位图，bit = bsp_key_id_t */
bool bsp_input_pressed(bsp_key_id_t id);
esp_err_t bsp_input_set_long_press_ms(uint32_t ms);
```

上层 `key_service` 把单键事件与组合键结果转成 `EVT_KEY` 投递到事件总线。
驱动本身不直接依赖 `svc_event`，方便游戏固件绕过事件总线直接读状态位。

### 6.4 bsp_imu

**硬件**：LSM6DS3TR-C，I2C SDA=1、SCL=2，地址 `0x6A`；INT1/INT2 未连接，
**只能轮询**。I2C 400 kHz。

**初始化序列（LSM6DS3TR-C，以实测为准）**：

| 寄存器 | 值 | 含义 |
|---|---|---|
| `0x0F` WHO_AM_I | 期望 `0x6A` | 不存在或不匹配则返回错误 |
| `0x12` CTRL3_C | `0x44` | BDU=1，IF_INC=1 |
| `0x10` CTRL1_XL | `0x40` | 104 Hz，±2 g |
| `0x11` CTRL2_G | `0x40` | 104 Hz，245 dps |
| `0x22`–`0x2D` | 12 字节 | 陀螺 + 加速度原始值 |

- 灵敏度：±2 g 为 0.061 mg/LSB；245 dps 为 8.75 mdps/LSB。
- 驱动任务默认 100 Hz 采样；只保留最新样本（互斥保护），不排队，
  避免消费慢时堆积。
- 上层注册可选回调做手势判断；**不要每个样本都发事件总线**，只在
  "摇晃/倾斜/翻转"状态变化时发 `EVT_IMU`。
- 连续读失败 3 次记一次 WARN 并尝试重新初始化总线；不重启系统。

**接口**：

```c
typedef struct {
    int16_t ax, ay, az;      /* 原始值 */
    int16_t gx, gy, gz;
} bsp_imu_raw_t;

typedef struct {
    float ax_g, ay_g, az_g;
    float gx_dps, gy_dps, gz_dps;
    uint32_t timestamp_ms;
} bsp_imu_sample_t;

esp_err_t bsp_imu_init(uint32_t sample_hz);
esp_err_t bsp_imu_deinit(void);
esp_err_t bsp_imu_read_latest(bsp_imu_sample_t *out);
esp_err_t bsp_imu_set_callback(void (*cb)(const bsp_imu_sample_t *, void *), void *ctx);
esp_err_t bsp_imu_get_stats(bsp_imu_stats_t *out);
```

### 6.5 bsp_audio

**硬件**：

| 方向 | 器件 | 引脚 | I2S |
|---|---|---|---|
| 录音 | MSM261（I2S 数字麦） | BCLK=11、WS=12、DATA=10 | I2S0 RX |
| 播放 | MAX98357（数字功放） | BCLK=46、LRC=9、DIN=3 | I2S1 TX |

**配置**：

- 采样：麦克风 16 kHz / 16 bit / 单声道；功放支持 16 kHz 与 24 kHz。
- 两个通道都配置为 **Master**，由 ESP32-S3 输出 BCLK/WS。
- 麦克风为 24 bit 数据时，按 32 bit 槽接收后取高 16 bit；具体槽宽在
  bring-up 时以实测波形为准。
- 音量：MAX98357 硬件增益由板上电阻决定，软件只做 0–100% 数字增益。
- 环形缓冲：RX/TX 各 4 KB，放内部 RAM；DMA 缓冲 2–4 块。
- 驱动不创建业务任务；上层 `audio_task` 调阻塞读写接口。PTT 录音时
  由上层决定缓冲到 PSRAM 还是直接上传。

**接口**：

```c
esp_err_t bsp_audio_init(void);
esp_err_t bsp_audio_deinit(void);
esp_err_t bsp_audio_mic_read(void *buf, size_t bytes, size_t *out_bytes, uint32_t timeout_ms);
esp_err_t bsp_audio_spk_write(const void *buf, size_t bytes, uint32_t timeout_ms);
esp_err_t bsp_audio_set_volume(uint8_t percent);
esp_err_t bsp_audio_get_stats(bsp_audio_stats_t *out);
```

**注意事项**：

- GPIO3、GPIO46 是 Strapping 脚，MAX98357 的 DIN/BCLK 默认下拉，正常上电
  不会改变启动模式；bring-up 时必须确认复位/上电无异常，必要时在驱动
  初始化前把两脚设为低电平输出。
- I2S DMA 回调与读写热路径禁止日志。
- 欠载/溢出只累加统计，不打印；由上层状态页按需读取。
- 关闭 I2S 时先 `i2s_channel_disable` 再删通道，避免切换固件瞬间爆音。

### 6.6 bsp_storage

**组成**：

| 存储 | 用途 | 要点 |
|---|---|---|
| NVS | 设置、Wi-Fi、BLE 配对、API Key | 三套固件共享，key 加模块前缀；初始化需处理 `NO_FREE_PAGES`/`NEW_VERSION` |
| microSD | ROM、存档、资源 | SPI3：CS=38、CLK=40、MOSI=39、MISO=41；20 MHz 起步 |
| assets | 字体、表情、音效 | SPIFFS，分区标签 `assets`，挂载 `/assets`，只读 |

- SD 使用 `esp_vfs_fat_sdspi_mount("/sdcard", ...)`，`max_files=8`，
  `allocation_unit_size=16 KB`，`format_if_mount_failed=false`。
- **没有卡检测脚**：启动时重试 3 次（间隔 200 ms）；之后不承诺热插拔，
  插入新卡由上层显式调用 `bsp_storage_sd_mount()` 重试。
- assets 当前尚未写入内容，挂载失败只记录 WARN，不影响启动。
- NVS 只有 16 KB，Wi-Fi + BLE 同时使用时偏紧；驱动不做额外占用，
  上层设置项要控制大小。

**接口**：

```c
esp_err_t bsp_storage_nvs_init(void);
esp_err_t bsp_storage_init(void);
esp_err_t bsp_storage_sd_mount(void);
esp_err_t bsp_storage_sd_unmount(void);
bool      bsp_storage_sd_ready(void);
esp_err_t bsp_storage_assets_mount(void);
const char *bsp_storage_sd_path(void);      /* "/sdcard" */
const char *bsp_storage_assets_path(void);  /* "/assets" */
```

### 6.7 bsp_power

- **LED**：GPIO18，低电平点亮；提供 `bsp_power_set_led(bool on)`，不参与状态机。
- **背光**：由 `bsp_display_set_backlight()` 控制；空闲 30 s 降到 50%、
  60 s 进入 Light Sleep 的策略放在框架层，驱动只提供原子操作。
- **Light Sleep**：把 8 个按键 GPIO 配置为 `GPIO_INTR_LOW_LEVEL` 唤醒，
  `esp_sleep_enable_gpio_wakeup()` + `esp_light_sleep_start()`；唤醒后
  重新初始化 I2S 与背光，屏幕按需恢复。
- **没有电池采样**：不提供电量/充电状态接口，不写假数据。
- 关机由 SW1 硬件切断，驱动不参与。

**接口**：

```c
esp_err_t bsp_power_init(void);
esp_err_t bsp_power_set_led(bool on);
esp_err_t bsp_power_sleep(uint32_t key_mask);   /* bit = bsp_key_id_t */
esp_err_t bsp_power_get_stats(bsp_power_stats_t *out); /* sleep/wake 次数 */
```

Light Sleep 属于第 13 周任务；驱动先提供接口与最小实现，联调阶段单独验证
"睡死唤不醒"问题，做 100 次睡眠/唤醒循环。

## 7. 内存与任务预算

| 项目 | 位置 | 预算 |
|---|---|---|
| LVGL 局部绘制缓冲 | 内部 RAM | 2 × 240×40×2 = 38.4 KB |
| NES 全帧缓冲 | PSRAM | 240×280×2 = 134.4 KB |
| LCD DMA bounce buffer | 内部 RAM | 2 × 16 KB = 32 KB |
| 音频 RX/TX 环形缓冲 | 内部 RAM | 2 × 4 KB = 8 KB |
| 按键事件队列 | 内部 RAM | 32 × 8 B ≈ 256 B |
| IMU 最新样本 | 内部 RAM | < 64 B |
| LVGL 堆 | PSRAM 优先 | 64–96 KB（框架层） |

| 任务 | 优先级（建议） | 栈 | 归属 |
|---|---|---|---|
| `bsp_input` 扫描任务 | 6 | 3 KB | 驱动 |
| `bsp_imu` 采样任务 | 3 | 3 KB | 驱动 |
| `audio_task` | 7 | 4–6 KB | 框架/应用 |
| `lvgl_task` | 4 | 8–12 KB | 框架 |
| `net_task` | 2 | 6–8 KB | 框架 |
| `app_task` | 5 | 6–8 KB | 应用 |

具体数值以实测堆水位为准；驱动创建的任务在 `bsp_*_deinit()` 里必须删除。

## 8. 与上层的衔接

> 角色、切固件、NVS、SD/assets、事件 ABI 的完整契约见
> [07 共用层与契约](07-共用层与契约.md)。

- **事件总线**：当前 `app_event_t` 的 payload 只有 `key_id`/`code`，
  需要扩展为按键事件（键 + 类型 + 按住时长）和手势事件。IMU 原始样本
  不经过事件总线，避免 100 Hz 淹没队列。
- **LVGL 适配层**：在框架层实现，调用 `bsp_display_flush()` 与
  `bsp_input_state()`；驱动不 include LVGL。
- **按键组合**：`key_service` 读取 `bsp_input_state()` 位图，识别
  `START+B`、`CTRL+方向`，再投递语义事件。
- **三个固件**：`factory` 用全部驱动；`game` 用 display/input/audio/storage，
  不需要 IMU 时可跳过；`ai` 用 display/input/imu/audio/storage。

## 9. 联调顺序与验收

| 步骤 | 内容 | 通过标准 |
|---|---|---|
| 1 | 控制台改 USB Serial/JTAG | 串口无乱码；LCD_DC(43)/LCD_BL(44) 不再被日志翻转 |
| 2 | 背光 + LED | 上电不白屏；背光 0–100% 连续可调；LED 极性正确 |
| 3 | ST7789 点屏 | 满屏色块无偏移、无花屏；Y 偏移 20 正确；连续刷 1000 帧不崩 |
| 4 | 8 键 | 每键 DOWN/UP 正确；20 ms 抖动被滤除；长按阈值可配 |
| 5 | IMU | WHO_AM_I=0x6A；静置读数稳定；摇晃/翻转能被上层识别 |
| 6 | SD + assets | 插卡可列目录；拔卡不崩；挂载失败不阻塞启动 |
| 7 | I2S | 录音回放无爆音；`mic_overrun`/`spk_underrun` 长时间为 0 或可解释 |
| 8 | 日志关闭 | `LOG_LEVEL_WARN` 下重复 3–7，功能与帧率无差异 |
| 9 | 三固件 | 三套固件都能独立初始化驱动并进入各自界面 |

## 10. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| UART0 日志占用 GPIO43/44 | 花屏、背光闪烁 | 控制台改 USB Serial/JTAG，验收时检查两脚无日志波形 |
| PSRAM 直接 SPI DMA | 花屏/崩溃 | 驱动内部统一切到内部 RAM bounce buffer |
| 背光上电默认常亮 | 开机白屏 | `bsp_board_early_init()` 第一行拉低 GPIO44 |
| GPIO3/46 为 Strapping 脚 | 启动模式异常 | bring-up 验证上电/复位；必要时初始化前拉低 |
| SD 无卡检测 | 热插拔不可靠 | 启动重试 + 上层显式重挂载，不承诺中断 |
| NVS 仅 16 KB | Wi-Fi+BLE 配置可能不足 | 控制设置项大小；后续评估扩到 24 KB |
| 日志写在热路径 | 帧率/音频抖动 | 驱动只留统计接口，评审时检查 flush/ISR 无 `ESP_LOG` |
| 主工作树无法 lock | 自动工作流第一步失败 | 从 linked worktree 开始执行工作流（见 CLAUDE.md） |

## 11. 实施顺序（Definition of Done）

1. 修 console 配置，三工程重新生成 `sdkconfig` 并编译通过。
2. `bsp_board` + 背光/LED，串口可验证。
3. `bsp_display` 点屏，LVGL 适配层之前先做色块/帧率 demo。
4. `bsp_input` 8 键事件。
5. `bsp_imu` 轮询与手势接口。
6. `bsp_storage` NVS/SD/assets。
7. `bsp_audio` 录放回环。
8. `bsp_power` Light Sleep（第 13 周）。
9. 三个固件接入驱动，按第 9 节逐项验收。
10. 分别在 INFO/WARN 日志级别下回归，确认日志不影响功能。
